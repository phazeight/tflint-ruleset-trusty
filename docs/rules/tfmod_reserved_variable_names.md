# `trusty_reserved_variable_names`

**Severity:** ERROR
**Scope:** all `variable` blocks, every module tier

## Summary

Flags variables whose name Terraform reserves as a meta-argument inside `module` blocks. This is not a style preference — a module containing such a variable **cannot be initialised at all**:

```
Error: Invalid variable name

  on inputs.tf line 63, in variable "version":
  63: variable "version" {

The variable name "version" is reserved due to its special meaning inside
module blocks.
```

## Reserved names

`count` · `depends_on` · `for_each` · `lifecycle` · `providers` · `source` · `version`

## Rule checks

| Check | Trigger | Message |
|-------|---------|---------|
| Reserved variable name | `variable "<reserved>"` | `variable "X" uses a name Terraform reserves in module blocks; the module cannot be initialised. Rename it ... and map it back in main.tf` |

## Why atoms hit this

Atoms mirror a provider resource one-to-one, and several AWS resources expose a `version` attribute — `aws_eks_cluster`, `aws_eks_node_group`. A naive 1-to-1 atom therefore generates `variable "version"` and is dead on arrival.

The fix is to rename the variable and map it back in `main.tf`:

```hcl
# inputs.tf
variable "kubernetes_version" {
  type        = string
  default     = null
  description = "Kubernetes minor version. Maps to the resource's `version` argument."
}

# main.tf
resource "aws_eks_cluster" "this" {
  version = var.kubernetes_version
}
```

`scripts/scaffold-atom.py` in the module repo carries a `VARIABLE_RENAMES` table for this and exits rather than emitting an unusable module.

## Interaction with `trusty_atom_full_inputs`

`trusty_atom_full_inputs` compares defined variables against `resource_schemas.go`, which is **generated** by `scaffold-atom.py`. Because the generator records the *emitted* variable name, the table holds `kubernetes_version` and the two rules agree.

If the table is ever regenerated by a generator that lacks the rename table, it will record `version`, and `trusty_atom_full_inputs` will demand a variable that cannot legally exist. This rule makes that conflict explicit instead of an unexplained loop.

## Notes

- Only `variable` block **labels** are checked. A reserved word used as a resource attribute (`version = var.kubernetes_version`) or as a field inside an object type (`launch_template = { version = string }`) is legal and is not flagged.
- Applies at every tier, not just atoms — the Terraform restriction is universal.
